# NGUID (Namespace Globally Unique Identifier)

It is a 128-bit (16-byte) value assigned to an NVMe Namespace that is guaranteed to be unique across the entire world. No two namespaces, on any drive from any manufacturer, should ever have the same NGUID.

1. Core Purpose

    The primary purpose of the NGUID is to **provide a persistent, hardware-based identity for a namespace**.

    - Persistence: Unlike a Namespace ID (NSID), which is a logical number (1, 2, 3...) that can change if the namespace is deleted and recreated, the **NGUID is "burned" into the namespace metadata**. It stays with the namespace even if it is moved to a different controller or the drive is reformatted (unless explicitly overwritten).
    - Global Uniqueness: It allows software (Operating Systems, Hypervisors, Storage Clusters) to distinguish between namespaces even if they have the same label, size, or NSID.

2. NGUID vs. NSID vs. EUI64
It is crucial to distinguish NGUID from other [[identifiers]]:

    |Identifier|Size|Scope| Mutability|Usage|
    |---|---|---|---|---|
    |NSID|32-bit integer|Local to the controller|Volatile. Changes if namespace is deleted/recreated|Used for addressing commands (e.g. "read from NSID1")|
    |NGUID|128-bit (16 bytes)|Global. Unique worldwise|Persistent. Stays with the namespace data|Used fro tracking, clustering, and persistent mounting|
    |EUI64|64-bit (8 bytes)|Global. Unique worldwide|Persistent|Legacy identifier (from SCSI/SAS). Oftern used if NGUID is not supported|

    Note: A namespace will typically have either an NGUID or an EUI64, but modern NVMe drives (1.3+) prefer NGUID.

3. How It Is Structured

    The NGUID is a raw 128-bit value. It does not have a strict internal format defined by the NVMe spec (unlike UUIDs which have version/variant bits), but manufacturers usually construct it using:

    - IEEE OUI (Organizationally Unique Identifier): The first 24 or 36 bits identify the manufacturer (e.g., Samsung, Intel).
    - Vendor Specific Extension: The remaining bits are a serial number or hash generated by the vendor to ensure uniqueness.

4. Where to Find It

    You can retrieve the NGUID using the Identify Namespace command.

    - Command: `nvme id-ns /dev/nvmeXnY` (in Linux).
    - Location in Data Structure: Bytes 127:112 of the Identify Namespace data structure.
    
    Example Output (Linux nvme-cli):

    ```
    $ sudo nvme id-ns /dev/nvme0n1
    ...
    nguid   : 5cd2e40b91f5a3c8001a4a0001234567
    eui64   : 0000000000000000
    ...
    ```

    (Note: In this example, eui64 is 0, meaning the drive uses NGUID as the primary global ID.)

5. Practical Use Cases

    A. Clustered File Systems & Databases
    In environments like VMware vSAN, Microsoft Cluster Shared Volumes (CSV), or Oracle RAC, multiple servers access the same storage.

    - If a drive fails and is replaced, or if a namespace moves from Controller A to Controller B, the NSID might change (e.g., from 1 to 5).
    - The cluster software uses the NGUID to recognize: "Ah, this is the same data volume I was using before, even though its NSID changed." This prevents data corruption and ensures the correct volume is mounted.

    B. Persistent Device Naming in Linux
    Linux uses the NGUID to create persistent device names in `/dev/disk/by-id/`.

    - Instead of /dev/nvme0n1 (which might become `/dev/nvme1n1` after a reboot if drive order changes), the OS creates a link like:
        `/dev/disk/by-id/nvme-eui.5cd2e40b91f5a3c8001a4a0001234567`
    - This ensures that your filesystem mounts the correct drive every time, regardless of physical slot order.

    C. Namespace Migration

    If you detach a namespace from one NVMe subsystem and attach it to another (using NVMe-oF or dynamic namespace management), the new controller will assign it a new local NSID, but the NGUID remains unchanged, allowing the host to track the data's location.

6. NGUID vs. UUID (Universal Unique Identifier)

    You might also see a UUID field in the Identify Namespace structure (introduced in NVMe 1.3).

    - NGUID: Raw 128-bit value. Simple, efficient for hardware.
    - UUID: Follows the RFC 4122 standard (has specific bits for version/time).
    - Relationship: They serve the same purpose. If a namespace has a UUID, it is often preferred by modern OSs for compatibility with standard UUID tools. If not, they fall back to NGUID. If neither exists, they fall back to EUI64.

## Summary
- NGUID = Namespace Globally Unique IDentifier.
- It is a 128-bit persistent ID for an NVMe namespace.
- It survives reboots, controller resets, and namespace re-attachments.
- It is critical for storage clustering, virtualization, and persistent mounting in operating systems.
- It is retrieved via the Identify Namespace command.
